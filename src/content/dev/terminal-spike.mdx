Terminal Spike is my open-source native Android terminal for working on remote machines from a phone. SSH, built-in Mosh, Herdr, tmux, and file transfers live in one workspace, with connection details stored on the device.

[Get it on Google Play](https://play.google.com/store/apps/details?id=com.yanjiyu.terminalspike) · [View source](https://github.com/Anderbone/terminal-spike) · [Download releases](https://github.com/Anderbone/terminal-spike/releases)

## Herdr is the centre of my workflow

I use [Herdr](https://herdr.dev/docs/) on my computer to organise projects, terminal panes, and coding agents. Its background server keeps terminal sessions running when I detach, so I can return from my phone to the work already in progress. Agent status helps me see which pane is working and which needs attention.

Terminal Spike understands Herdr sessions and pane layout metadata. Its connection picker lets me resume a running Herdr session, and touch handling makes navigating spaces, tabs, and agents practical on a small screen. Tap to navigate; double-tap to bring up the keyboard.

Scrolling needs to respect the application inside each pane. Where Herdr exposes usable pane history, Terminal Spike offers a native scrollback reader. Interactive applications can use remote mouse input instead. That distinction matters when a coding agent owns its own transcript UI.

![Terminal Spike connection picker offering a running Herdr session alongside tmux sessions](/images/terminal-spike-herdr.jpg)

Herdr is a separate open-source project. My work here is the Android client and its integration with that remote workspace.

## Follow the work into code and notes

Terminal output often points to the next thing I need: a file, a browser editor, or a project note. Terminal Spike recognises web URLs and `obsidian://` links, including terminal hyperlinks, so those references can open in the appropriate app.

In my setup, code-server gives me a browser editor, Obsidian holds project notes, and [Pi Edge](/dev/pi-edge) brings Pi into Obsidian. Tailscale connects my devices when I am away from home. I describe how these pieces fit together in [my current workflow](/dev/workflow-anywhere).

## Remote work from a phone

The app supports password and private-key SSH authentication, saved connections, and several simultaneous terminal tabs. It verifies server host keys and warns when a known server's key changes.

Alongside the terminal, there is an SFTP file manager for browsing, uploading, downloading, renaming, and deleting remote files. Saved command snippets and a configurable extra-key bar make frequently used commands and keys such as Ctrl, Esc, and the arrows easier to reach. Fonts, colours, text size, and cursor behaviour are configurable too.

One useful part of the remote coding workflow is image input. Terminal Spike can transfer a clipboard image over an authenticated SSH connection to a private cache directory on the connected host, then paste its remote path into the terminal. That lets a remote tool work with an image from the phone.

## Building the terminal

The app uses Kotlin and Jetpack Compose for its application UI. The terminal itself is a custom Android View that draws rows directly with Canvas and Paint. That separates the terminal's rendering and screen state from the surrounding connection lists, settings, and session controls.

The terminal engine handles primary and alternate screens, cursor movement, scroll regions, colours, bracketed paste, and common terminal queries. Scrollback is bounded. For app-selected tmux sessions, a separate local history model supports scrolling on the phone, while an explicit remote-mouse mode is available for interacting with terminal applications that use it.

Mosh is built into the app. It starts through SSH, then uses its encrypted UDP transport to make an interactive session more tolerant of network interruptions. The connected computer needs `mosh-server`; Herdr or tmux keeps the remote workspace available independently of the phone connection.

## Keeping data on the device

Terminal Spike has no app account, analytics, advertising, or cloud-sync service. Connections go directly to the hosts the user chooses. Imported private keys and passwords that the user explicitly chooses to save are encrypted using an app-specific Android Keystore key.

The [privacy policy](/projects/terminal-spike/privacy/) explains credential storage, remote connections, permissions, and backups in more detail.
